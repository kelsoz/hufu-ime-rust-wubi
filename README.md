# 虎符 HuFu · Wubi86 适配版

本项目是基于 [LeafHW/hufu-ime-rust](https://github.com/LeafHW/hufu-ime-rust) 的衍生版本，不是上游官方发行版，也不是从零实现的输入法。

代码基线为上游 `v1.9.9.9`（commit [`d438807`](https://github.com/LeafHW/hufu-ime-rust/commit/d438807db679631451dd6b47fe6d610350aaa075)）。上游项目提供了 Rust 引擎、Windows TSF / Linux fcitx5 / macOS IMK 前端、图形设置页、皮肤、同步和整句模型等主体功能；本仓库只在其上补充五笔短码输入时的候选补全与编码注释细节。

## 相对上游改了什么

| 范围 | 本仓库的改动 |
| --- | --- |
| 配置 | 新增 `input.prefix_completion` 与 `candidates.show_code_comment`，均默认关闭；旧配置缺少字段时保持关闭。 |
| 候选生成 | 开启前缀补全后，普通单码路径保留精确候选原序，再追加编码严格更长且以当前编码开头的主码表候选。 |
| 排序与过滤 | 追加候选按权重降序、原码表顺序升序；同词保留最优编码，过滤已软删条目，并按每页候选数限量。 |
| 候选交互 | 补全候选保留完整编码；整句候选状态下按数字选择显示项时，可直接提交对应的长码补全候选。 |
| 简繁与 Emoji | 只对新增补全候选执行 OpenCC / Emoji 处理，避免重复处理已有精确候选。 |
| 候选注释 | “显示拼音注释”扩展为“关闭 / 拼音 / 五笔”三选一；拼音与五笔编码互斥，五笔模式显示单字和词语的完整候选编码。 |
| 设置页 | 在当前 React 设置页和旧版设置页增加前缀补全开关及三选一候选注释，并加入设置搜索。 |
| 验证 | 增加配置兼容、排序、去重、软删过滤、限量、开关切换、数字选择和注释模式等回归测试。 |

没有重写上游的输入法前端、皮肤、云同步或整句模型；关闭“前缀补全”后，候选行为与上游基线一致。

## 前缀补全怎么用

1. 编译或安装包含本仓库改动的版本。
2. 打开设置页，进入“输入 → 编码”，开启“前缀补全”。
3. 输入短码后，精确候选仍排在最前，其后出现同前缀的长码候选。

例如使用 Wubi86 码表输入 `tj` 时，精确候选“得”保持在首位，后续可出现“利于”“篮球”“复核”“得分”等 `tj` 开头编码的候选。实际顺序取决于当前码表的权重和原始顺序；候选本身保留 `tjgf`、`tjsy` 这样的完整编码，开启“五笔”候选注释后可直接显示在候选旁。

配置文件对应字段：

```json
{
  "input": {
    "prefix_completion": true
  },
  "candidates": {
    "page_size": 8
  }
}
```

补全只使用主码表，不把用户词、个人存储表中的长码混入短码候选；反查、快符、通配符、反引号超集以及整句锁 / 超长码接管路径不启用该功能。

## 候选注释怎么用

打开设置页，进入“输入 → 候选”，在“候选注释”中选择：

- **关闭**：不显示拼音或五笔编码注释。
- **拼音**：沿用上游的拼音注释；单字优先读取 `数据\注释\拼音.注释`，无表时回退反查表。
- **五笔**：显示当前候选的完整编码，包括前缀补全产生的长码候选和词语候选。

拼音和五笔编码不会同时显示；旧配置中的 `show_pinyin_comment: true` 会自动对应“拼音”。整句输入模式下两类注释均暂不显示，切换回码表方案后恢复。
